# 国密合规（商用密码）

检查「该用国密的地方，有没有还在用国际算法或不安全参数」。

## ⚠️ 先读这一段：这是【条件性要求】

**国密不是所有项目都强制。** 只有**涉及商用密码的场景**才有要求 ——
关键信息基础设施、等保三级及以上、金融/政务/能源等有行业规定的领域、
需要过**密评**（商用密码应用安全性评估）的系统。

所以本插件的**每一条规则都用 `when` 限定**：只有扫描到的文本里能匹配到
「密码学代码」的特征（`crypto` / `Cipher` / `encrypt` / `MessageDigest` /
`hashlib` / `AES` / `RSA` …），规则才运行。

**纯业务代码的项目上，5 条规则一条都不会跑**，报告里会标注为「不适用」而不是「通过」。
这是设计如此 —— 在无关项目上报「你没用国密」是纯噪声。

## 一、依据

| 标准/法规 | 用在哪 |
|---|---|
| **GB/T 39786-2018**《信息安全技术 信息系统密码应用基本要求》 | 总纲：密码算法与工作模式应符合国家密码管理部门的规定 |
| **GB/T 32918 系列**《信息安全技术 SM2 椭圆曲线公钥密码算法》 | 公钥算法 |
| **GB/T 32905-2016**《信息安全技术 SM3 密码杂凑算法》 | 杂凑算法 |
| **GB/T 32907-2016**《信息安全技术 SM4 分组密码算法》 | 分组密码 |
| **《中华人民共和国密码法》第二十七条** | 关键信息基础设施运营者应当使用商用密码进行保护，并开展商用密码应用安全性评估 |
| **OWASP Cryptographic Storage Cheat Sheet** | 具体的不安全用法：ECB、MD5/SHA-1、RSA<2048、硬编码 IV/salt |

## 二、它查什么（5 条）

| 级别 | 规则 | 查什么 |
|---|---|---|
| 🔴 高 | `CRYPTO-ECB` | ECB 模式；含 Java `Cipher.getInstance("AES")` 未指定模式（默认即 ECB） |
| 🔴 高 | `CRYPTO-WEAK-HASH` | MD5 / SHA-1 的调用点与算法名字符串 |
| 🔴 高 | `CRYPTO-RSA-KEYLEN` | RSA 密钥长度 512 / 1024 / 1536 |
| 🔴 高 | `CRYPTO-HARDCODED-IV` | IV / salt 是字符串字面量，或 `IvParameterSpec("...")` |
| 🟡 中 | `CRYPTO-NO-SM` | 有密码学代码但全项目找不到 SM2/SM3/SM4（absence 判定） |

## 三、为什么 ECB 是重点

ECB 是**确定性**模式 —— 相同明文分组永远加密成相同密文分组，
数据的重复结构直接暴露在密文里。它没有链接、没有 IV，无法提供语义安全。

最容易漏的是 Java：

```java
Cipher.getInstance("AES")                     // ← 默认 ECB/PKCS5Padding
Cipher.getInstance("AES/ECB/PKCS5Padding")    // ← 显式 ECB
Cipher.getInstance("AES/CBC/PKCS5Padding")    // ← 正确写法
```

只写 `"AES"` 看起来「没选模式」，实际上选了一个最差的。
替代方案：CBC/CTR/GCM 这类带链接或带认证的模式；改用国密则对应 SM4/CBC、SM4/GCM。

## 四、`CRYPTO-NO-SM` 怎么读（最容易被误读）

它是 `files-lack` + `when`：**在有密码学代码的项目里，找不到国密的痕迹**。

报出来 = **提示确认**，不等于违规。正确处理顺序：

1. 这个项目是否落在商用密码的应用范围内？
2. 在范围内 → 公钥换 SM2（GB/T 32918）、杂凑换 SM3（GB/T 32905）、
   分组加密换 SM4（GB/T 32907），并选用通过认证的密码模块。
3. 不在范围内 → 忽略本条，并在项目文档里写明理由，便于日后密评时说明。

## 五、怎么用

```bash
<cli 路径> --demo          # 看检出效果（内置样本，故意有问题的项目）
<cli 路径> --list-rules    # 列出规则和依据
<cli 路径> --html r.html   # 报告给安全负责人
<cli 路径> --json          # 给 CI 二次处理
```

## 六、边界（不要过度解读报告）

- **不做缺项判定** —— 没看到国密不等于违规（见第四节）。
- **不看部署层** —— 密码机、KMS、网关侧的统一加密不在扫描范围。
- **不校验密码模块资质** —— 用了 SM4 也不代表用的是通过认证的模块。
- **不判断密钥管理** —— 轮换、分级、托管都不在范围。
- **MD5 用于非安全用途不算** —— 缓存键去重、对象存储 ETag 不属于安全用途。
- **报出来是提示确认，不是判定违规。**

## 七、覆盖面

5 条，覆盖「算法选型（国密 vs 国际） + 参数安全（模式 / 长度 / IV）」
这两个最容易在密评里被问到的问题。
